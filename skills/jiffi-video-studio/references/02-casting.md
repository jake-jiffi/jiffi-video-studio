# Stage 2: Assets and visual direction

Select the assets this project needs. People, reference sheets and generated
locations are conditional. Skip this stage when the approved supplied media
already determines the visual direction.

Inventory existing footage, audio, graphics and references first. Preserve
originals in `source/`, record provenance and inspect quality. Missing real
footage may require a capture or shoot plan; generating a fictional substitute
does not prove a real event occurred.

## New or recurring subjects

Reuse suitable entries in `cast-registry.json`. A different outfit can be a
sheet variant under the same identity. Reference images can improve identity
consistency but do not guarantee it; inspect each rendered take.

For speaking characters, keep the selected voice/preset and vocal reference
with the visual identity. Match delivery to the role and performance. Scene
acoustics belong in the project's sound plan, so changing locations preserves
the character's identity. Follow `09-scene-sound.md` before new voice generation.

For a generated person, animal, creature or object, specify the features that
must stay stable, in the requested style. Create only enough alternatives to
resolve a real choice, within budget. Photoreal portraits and four options are
not universal requirements. Distinct silhouettes and colours help when several
subjects share a frame. Avoid adding an accessory unless the story needs it.

Use views and expressions needed by the shots for a recurring character's
sheet. Check identity, proportions, surface detail and wardrobe across panels.
A simple product shot may need only its supplied product image. Generated
character registry entries retain a master and sheet; an inspected existing
reference can serve both when extra views add no value. Do not invent unseen
details of a real product and present them as accurate.

For real people, record consent and use suitable supplied images or footage.
Ask for more views only if the planned generation needs them. Editing an
interview does not require synthesising a portrait or training an identity.
Inspect provided assets for client or internal information under SKILL.md.

## Locations and objects

For a continuous scene, establish a master layout and derive needed views from
it. Different locations or times get separate scene IDs; do not force the whole
film into one room. Only create extra angles when coverage needs them.

Give a story-critical or recurring object an identifiable reference or source
frame. Record its geometry and condition. Use supplied authorised branding when
the brief needs it, otherwise use generic props. Apply the continuity checks
to both generated and filmed coverage.

## Gate 2, when needed

Show unresolved cast or visual choices as a labelled contact sheet, with a
recommendation. Reused or explicitly specified assets need no new selection.
If there is nothing to choose, mark the gate not applicable in the brief.

Save selected reusable assets in the studio registry without overwriting old
entries. Record real-person consent as `yes, YYYY-MM-DD, confirmed by <reviewer name>`.
A recorded real subject needs a reference master (an authorised source frame
is sufficient); a synthetic multi-view sheet is optional. Source footage and
project-specific consent evidence remain with the project.

For recurring generated characters, an optional Soul ID may help additional
stills in compatible Higgsfield image models. Do not train one by default.
